SECTION 00

はじめに整える土台

作業フォルダと、AIに渡す情報

動画でお見せした9個は、どれも同じ土台の上に乗っています。Claude Codeはローカルフォルダで作業します。ローカルフォルダとは、MacでいうFinder、Windowsでいうエクスプローラーで見ているファイルやフォルダのことです。

この情報がない状態でAIに仕事を頼むと、どうしても一般論の出力になります。自分の商品情報、過去の発信、お客様の声が入っていると、自分の事業に合わせた判断がしやすくなります。まずはデスクトップアプリで作業フォルダを開くところから始めてください。

公式情報: Claude Code デスクトップアプリ クイックスタート / クイックスタート

作業フォルダ 一撃構築プロンプト

作業フォルダ構築プロンプト 
このフォルダを、Claude Codeで自分の事業の業務を進めるための作業フォルダとして整理してください。

目的は、AIが自分の事業情報・商品情報・過去の制作物・業務ルールを読み取り、実務に使える出力を作れる状態にすることです。

以下の方針でフォルダ構造を作成してください。

1. 事業・商品の情報
- 事業概要
- 商品、サービス、価格
- ターゲット、顧客情報
- よくある質問

2. 過去の発信
- YouTube台本
- X投稿
- LINE配信
- セミナー資料
- LP、販売ページ

3. 実績・お客様の声
- 成果報告
- 感想
- 対談、インタビュー

4. 業務ごとの作業場所
- スライド
- アーカイブ共有
- SNS投稿
- リサーチ
- サムネイル
- 商品制作

5. AIに守らせるルール
- 言葉遣い
- 出力先
- 確認が必要な操作
- 扱ってはいけない情報

作成後に、
「どのフォルダに何を入れればいいか」
「最初に入れるべきファイル」
「不足している情報」
を初心者にも分かる言葉で説明してください。

ルールファイルを置く

フォルダを作ったら、AIに毎回守ってほしいルールを先に書いておきます。Claude CodeではCLAUDE.mdというファイルを使います。言葉遣い、出力先、触っていいファイル、確認が必要な操作をここに書いておくと、毎回同じ説明をしなくて済みます。

CLAUDE.md 作成プロンプト 
このフォルダの CLAUDE.md を作成してください。

以下を入れてください。

1. このフォルダの目的
2. 扱う事業、商品、ターゲット
3. 文章を書くときの言葉遣いと一人称
4. 出力先のルール（どのフォルダに何を保存するか）
5. 禁止事項
- 実績や数字を推測で作らない
- APIキーや顧客情報を外部に出さない
- 送信、投稿、決済、削除、権限変更を勝手に実行しない
6. 品質チェック項目

初心者にも分かる言葉で作成してください。
  • 最初から完璧な構造を目指さない。素材をまとめて渡して、AIに整理させる。
  • 顧客に届く操作、お金が動く操作、外部に公開される操作は人間確認を挟む。
  • APIキーは後述の.envで管理し、チャットに貼りっぱなしにしない。
SECTION 01

スライド作成

台本を渡して、画像として出す

これまでのAIスライドは、用意されたテンプレートに文章を当てはめる形が多く、実務で使うには物足りない場面がありました。台本を読み込ませて、内容に合わせてデザインを変えながら画像として出す形にすると、仕上がりがかなり変わります。

星川の場合、外注していた頃は1枚あたり数千円かかっていた部分が、1枚10円ほどで作れるようになり、手元に残る作業もほぼなくなりました。

手順

1. 台本を渡す

スライドにしたい台本や原稿を、そのままチャットに貼り付けます。

2. 画像生成を指定する

画像生成モデルを使うことを明示します。ここを書かないとコードベースの出力になることがあります。

3. 参考画像を渡す

過去に使ったスライドを送り、そのトンマナに寄せてもらいます。

- 完成した画像は指定のフォルダに保存する

SECTION 03

X投稿

素材集めから予約投稿までをつなげる

星川のXでは、受講生の成果報告を3日に1回ほど投稿しています。この投稿は、素材を拾うところから、文章を作り、画像を作り、予約投稿するところまでをAIで進めています。

ここで効いているのが、自分の過去投稿を読み込ませてあることです。口調や価値観のデータが入っているので、自分が書いたような文章が出てきます。

必要な接続

つなぐもの何のために使うか公式情報
チャットツール成果報告などの素材を読み取るChatwork API
X投稿の作成と予約X API
画像生成投稿に添えるクリエイティブOpenAI 画像生成

APIキーを安全に置く

外部ツールをつなぐときに必ず出てくるのがAPIキーです。APIキーは、AIが外部ツールを操作するための鍵のようなものです。従量課金のものもあるため、外部に出ると身に覚えのない請求につながる可能性があります。チャットに貼りっぱなしにしない、公開ドキュメントに書かない、SNSに載せない、公開フォルダに入れない。この4つを徹底してください。

APIキー安全管理プロンプト 
このフォルダで外部サービスのAPIキーを扱います。
APIキーが外部に流出しないように、安全な管理環境を作ってください。

以下を実行してください。

1. .env ファイルを作成する
- 本物のAPIキーを入れる場所として使う
- まだ実際のキーは入れず、仮の値だけ入れる

2. .env.example を作成する
- 他の人に共有しても問題ないように、キー名だけを書く
- 本物のAPIキーは絶対に入れない

3. .gitignore を確認する
- .env が外部に公開されないように除外設定を入れる

4. CLAUDE.md にセキュリティルールを追記する
- APIキーをチャットに出力しない
- APIキーをログに表示しない
- APIキーを外部URLへ送信しない
- 従量課金APIは料金体系を確認してから使う
- 送信、投稿、決済、削除、権限変更は勝手に実行しない
- 最初は読み取りや下書き作成など、小さい操作からテストする

5. 最初の疎通確認として、安全なテスト手順を提案する

6. 変更内容を初心者にも分かる言葉で説明する
.env サンプル 
CHATWORK_API_TOKEN=ここにChatworkのAPIキーを入れる
X_BEARER_TOKEN=ここにXのAPIキーを入れる

APIキーの扱い方はAPIキーのベストプラクティスも参考になります。

SECTION 06

24時間ナレッジ

自分の話し方をデータとして溜める

ナレッジとは、AIに読ませる自分の情報のことです。X投稿が自分の口調で出てくるのも、話し方や考え方のデータをAIに渡しているからです。

星川の場合、AIボイスレコーダーのPLAUDを付けて生活しています。喋った内容が自動で文字起こしされ、AIが読めるフォルダに溜まっていくので、起きている時間の発言がそのまま素材になります。

公式情報: Plaud MCP

溜めた音声を仕事につなげる

以下の形式で出してください。

- 要約
- 決定事項
- 未決定事項
- 担当者ごとのタスク
- 期限がありそうなもの
- 返信文の下書き
- 企画書や資料に反映すべき内容
- SNS発信やYouTube台本に使えそうな素材

推測で断定せず、
音声や文字起こしに根拠がある内容と
追加確認が必要な内容を分けてください。

送信や投稿は勝手に実行せず、下書きまで作ってください。

話し方のデータを抽出する

口調・文体の抽出プロンプト 
これまでの発信内容と文字起こしをもとに、私の話し方の特徴を抽出してください。

抽出してほしい項目
- 一人称
- よく使う語尾
- よく使う言い回し
- 改行のリズム
- 説明するときの順番
- 避けている表現

抽出したものはファイルにまとめて保存し、
今後の文章作成で毎回参照できるようにしてください。

記録に無い特徴を推測で足さないでください。
  • 録音には他の人の発言も入るため、扱いのルールを先に決める。
  • 顧客情報や機密が含まれる録音は、共有フォルダに置かない。
  • 抽出した口調データは、使いながら定期的に更新する。

商品作成

思いついた講座を、その日のうちに形にする

星川の場合、講座の教材ページもこの形で作っています。1本作るのに1時間もかかっていません。速く作れることよりも、思いついた内容をその日のうちに形にできるスピード感の方が効いています。

SECTION 10

自分にしか出せない出力

楽になるだけでは差がつかない

ここまでの9個をやると、お金も浮きますし、仕事も速くなります。ただ、それだけだと足りません。同じAIに同じ指示を出せば、同じような出力しか出てきません。誰でも作れるものを、速く作れるようになるだけです。

大事なのは、AIで自分にしか出せない出力を出すことです。そのために渡しているのが、次の3つです。

自分の人格と考え方

話し方、判断基準、価値観。文章の温度感がここで決まります。

ターゲットの言語化

お客様が考えていることを、0から100まで言葉にしたデータ。

商品と顧客の情報

提供している内容、価格、実績、よく来る質問。

この言語化をやっていく過程で、自分のビジネスの解像度がかなり上がります。ここまでやると、誰がどんなAIをどう使っても書けない文章が出せるようになります。

ナレッジ抽出プロンプト

3つのナレッジを整理する 
これまでの発信内容、商品情報、お客様とのやり取りを渡します。
以下の3つに分けて整理し、それぞれファイルに保存してください。

1. 自分の情報
- 一人称、話し方、語尾、よく使う言い回し
- 判断基準、価値観
- 経歴、実績（記録にあるものだけ）

2. ターゲットの情報
- どんな悩みを持っているか
- どんな言葉でその悩みを表現するか
- 何を諦めていて、何を求めているか
- よく来る質問

3. 商品の情報
- 提供内容と価格
- 得られる成果
- 他と違う点
- お客様の声

推測で埋めず、
根拠がある内容と、追加で確認が必要な内容を分けてください。

良い流れができたら固定する

納得できる出力ができたら、その流れをスキルにして固定します。スキルとは、AIに仕事の手順を覚えさせるものです。いきなり作らず、まず1回手動で最後まで通してから作るのがコツです。
